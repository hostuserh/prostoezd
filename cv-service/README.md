# ParkVision CV-сервис

Определяет занятость парковочных мест по городским камерам Владивостока
и отдаёт статусы на backend по контракту `POST /internal/occupancy` (см. `../CLAUDE.md`).

Целевой сервер: **4 ГБ RAM / 4 ядра, без GPU**. Все решения ниже продиктованы этим.

## Быстрый старт

```bash
pip install -r requirements.txt
python -m cvsvc.ingest.make_slate_ref --config config/cameras.yml   # эталон заглушки
python -m cvsvc.ingest.recorder --config config/cameras.yml --out frames --interval 20
```

## Что нужно знать про потоки vladlink

Это не теория — проверено вживую 13.11.2026 на всех трёх камерах.

### Referer обязателен, иначе приезжает заглушка

Без заголовка `Referer: https://vladlink.ru/` сервер отдаёт **HTTP 200 и валидное
h264-видео** — но это чёрный кадр с текстом «Трансляция заблокирована для данного
сайта» (`/static/slate/site.ts`). Никакой ошибки, никакого кода 403.

Без детекта заглушки сервис будет честно рапортовать «все места свободны» по
чёрному кадру. Поэтому проверка двойная:

- путь сегмента содержит `/static/slate/` (ловится на уровне плейлиста);
- aHash кадра близок к эталону `refs/slate.ahash` (ловится по содержимому).

### Архива (DVR) нет

Старые сегменты отдают **403**, окно плейлиста — 9 сегментов × ~7.5 с ≈ **60 секунд**.
Исторических кадров взять негде: любой датасет пишется живьём, начиная с момента
старта рекордера. Отсюда приоритет — рекордер запускается первым, до всего остального.

### ffmpeg не ест этот плейлист напрямую

URI сегментов не заканчиваются на `.ts` (это base64 от origin-URL), ffmpeg падает
на `is not in allowed_extensions`. Если всё же нужен ffmpeg поверх плейлиста:

```bash
ffmpeg -allowed_extensions ALL -extension_picky 0 \
  -headers $'Referer: https://vladlink.ru/\r\n' \
  -i "<playlist_url>" -frames:v 1 -y snap.jpg
```

Сам сервис так не делает: плейлист разбирается в `cvsvc/ingest/hls.py`,
ffmpeg получает уже скачанный сегмент.

### Как берём кадр дёшево

Постоянный ffmpeg-декодер на 3×1080p25 съедает 1.5–2 ядра. Вместо этого:

1. GET `index.m3u8` (~0.4 КБ);
2. берём **последний** сегмент;
3. качаем только `Range: bytes=0-500000` — сервер отдаёт `206`, и первого
   кейфрейма хватает на полный кадр (проверено на 2592×1944);
4. один проход ffmpeg даёт сразу JPEG на диск **и** 16×16 grayscale в stdout
   для aHash — без numpy.

Замер: **0.32 с CPU и ~0.5 МБ трафика на кадр**. Фолбэк на полный сегмент есть,
если в первых 500 КБ кейфрейма не оказалось.

## Камеры

| ID | Разрешение | Место | Пригодность |
|---|---|---|---|
| CAM-001 | 1920×1080 | Кольцо Багратиона | Карман внизу слева, авто 50–70 px. Разметки на асфальте нет → зоны. Мачта ЛЭП перекрывает часть, нижняя половина в тени. |
| CAM-002 | 1920×1080 | Центр / Светланская | Худшая: авто 25–45 px, перекрытия стройкой и деревьями. Только зоны. |
| CAM-003 | **2592×1944** | ТЦ Снеговая падь | Лучшая: размеченный краской паркинг, авто 80–120 px → дискретные места. Бочкообразная дисторсия. |

У камер **разное разрешение** — пиксельные координаты нигде не хардкодить,
`frame_size` в конфиге обязателен.

## Разметка ROI

`config/cameras.yml` — источник правды. Гибридная модель:

- **spots** — дискретные места. Только там, где на асфальте есть краска.
  `quad` — наземный след места (4 точки, по часовой), а не силуэт машины.
- **zones** — полигон + `capacity` + счётчик занятых. Для грунтовых и хаотичных
  площадок, где физических мест не существует. Не выдумываем ID мест там, где их нет.

Валидатор ловит: неуникальные ID, вырожденные полигоны, ROI вне кадра, квады
меньше 28 px (детектор такую машину не увидит), координаты вне Владивостока
и отсутствие Referer. Все проблемы выдаются списком сразу, а не по одной.

Координаты `lat`/`lon` ставятся руками по 2ГИС. Примеры в `CLAUDE.md`
(43.115141, 131.885341 — Clover House) — заглушка из спеки, к нашим камерам
отношения не имеет.

## Рекордер

```bash
python -m cvsvc.ingest.recorder --config config/cameras.yml --out frames \
    --interval 20 --max-age-days 7 --max-total-mb 20000
python -m cvsvc.ingest.recorder --once     # один цикл, для проверки
```

Пишет `frames/{CAM-ID}/{YYYYMMDD}/{HHMMSS}.jpg`, ротация по возрасту и объёму.
При интервале 20 с три камеры дают ~8 ГБ/сутки.

`frames/` в `.gitignore`: камеры публичные, но кадры содержат читаемые номера
и лица. Наружу уходят только агрегированные статусы.

### Детект зависшей картинки

Таймкод в углу кадра тикает каждую секунду **даже когда картинка замерла**.
Поэтому хеш для детекта зависания считается по кадру **без** областей
`overlay_exclude` (таймкод, вотермарка). Хеш по полному кадру всегда разный
и зависание не поймает — на этом легко обжечься.
