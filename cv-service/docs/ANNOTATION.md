# Разметка ROI: редактор и правила

Разметку рисует **человек глазами по кадру**. Автоматика здесь не даёт нужной
точности, поэтому `config/cameras.yml` — ручной артефакт, а `tools/annotate` —
инструмент, которым его правят.

> ⚠️ То, что лежит в `config/cameras.yml` сейчас, — **черновик**, сгенерированный
> расчётом по эталонным кадрам. Он проходит валидатор и годится для отладки
> детектора, но перед демо его обязан пройти человек. Что именно черновое —
> расписано комментариями в самом файле.

## Запуск

```bash
cd cv-service
python tools/annotate/server.py --port 8800
# → http://127.0.0.1:8800/
```

Зависимостей у редактора нет: статический HTML + CSS + vanilla JS на canvas,
сборка не нужна. `server.py` — stdlib: отдаёт статику и кадры, принимает YAML
и пишет `config/cameras.yml`, складывая предыдущую версию в `config/backups/`.

Без сервера тоже работает, но только на чтение:

```bash
python -m http.server 8080        # из каталога cv-service
# → http://127.0.0.1:8080/tools/annotate/
```

В этом режиме конфиг берётся статикой (`../../config/cameras.yml`), кадры
из `frames/` недоступны, записать на сервер нельзя — только «Скачать YAML»
и положить файл руками.

## Работа в редакторе

| Действие | Как |
|---|---|
| Режимы | <kbd>V</kbd> выделение, <kbd>S</kbd> место, <kbd>Z</kbd> зона, <kbd>O</kbd> overlay, <kbd>T</kbd> tile |
| Зум | колесо — к курсору; <kbd>F</kbd> — вписать кадр |
| Панорама | перетаскивание фона, либо <kbd>Space</kbd>+drag, либо средняя кнопка |
| Место | 4 клика по углам; потом углы таскаются мышью |
| Зона | N кликов по контуру, замыкание двойным кликом или <kbd>Enter</kbd> |
| Overlay / tile | drag по диагонали прямоугольника |
| Удалить | <kbd>Del</kbd> или кнопка в свойствах |
| Дублировать место | <kbd>D</kbd> — копия со сдвигом на свою ширину |

Кадр выбирается в шапке: эталон из `refs/` или любой кадр, накопленный
рекордером в `frames/{CAM-ID}/{YYYYMMDD}/`. Это полезно для проверки: разметка,
снятая по солнечному дню, должна попадать и по вечернему кадру.

Кнопка **Проверить** гоняет ваш YAML через тот же `cvsvc.config.load_config`,
что и детектор, и показывает список проблем. **Сохранить на сервер** не запишет
невалидный конфиг.

## Место или зона

Решение принято и не обсуждается — модель гибридная:

**spots** — дискретные парковочные места. Делаем **только там, где на асфальте
есть краска**. У места есть свой `id`, он уходит в backend и показывается
пользователю («ваше место S-305»).

**zones** — полигон + `capacity` + счётчик занятых. Для грунтовых и хаотичных
площадок, где физических мест не существует. Там **не выдумываем ID мест**:
пользователю честнее сказать «на площадке ~7 свободных», чем прислать его
на место S-417, которого никто никогда не размечал.

По камерам:

| Камера | Что делаем |
|---|---|
| CAM-003, ТЦ Снеговая падь (2592×1944) | Паркинг перед ТЦ и ряд внизу справа — **места** (авто 80–120 px). Грунтовые ряды слева вверху — **зона** (авто 40–55 px). |
| CAM-001, кольцо Багратиона (1920×1080) | Краски нет — **только зоны**. Под мачтой ЛЭП не размечаем либо ставим `enabled: false`. Нижняя половина кадра в глубокой тени. |
| CAM-002, центр (1920×1080) | Авто 25–45 px, перекрытия стройкой и деревьями. **Только зоны**, дискретных мест здесь не делать вообще. |

## quad — это наземный след, а не силуэт машины

`quad` — четыре угла **прямоугольника на асфальте**, который занимает одна
машина. Обход **по часовой, начиная с ближнего к камере левого угла**
(редактор рисует на этом углу жирную точку, чтобы порядок было видно).

Обводить силуэт стоящей машины **нельзя**. Камеры смотрят под косым углом:
корпус машины в кадре «уезжает» вверх от своего следа на земле, и квад,
снятый по крыше, перестаёт совпадать с местом, как только машина уедет —
а именно по пустому месту детектор и должен принимать решение. Размечайте
по краске и по теням на асфальте, а не по железу.

Если место сейчас занято и краски не видно — возьмите другой кадр из
`frames/`, где оно свободно.

## Минимум 28 px

Валидатор отклоняет место, у которого длинная сторона квада меньше **28 px**
в системе эталонного кадра: машину такого размера детектор не увидит, и место
будет вечно `unknown`. Редактор показывает длинную сторону в свойствах и в
списке объектов, и подсвечивает красным, когда она ушла ниже порога.

Если участок не дотягивает — это сигнал, что там не места, а **зона**.
Вариант «оставить, но выключить» — `enabled: false`.

## Дисторсия CAM-003

У CAM-003 заметная **бочкообразная дисторсия**: прямой ряд мест выглядит
в кадре **дугой**. Прогиб на ряд шириной ~750 px — около 25 px, это треть
ширины места.

Отсюда правило: **нельзя расставлять места линейной интерполяцией между
краями ряда** — крайние квады уедут с асфальта. Либо ставьте каждый квад
отдельно по краске, либо ведите ряд по дуге (квадратичная подгонка по трём
опорным точкам: два края ряда и середина). Кнопка <kbd>D</kbd> даёт линейный
дубль — после неё углы обязательно подвинуть по картинке.

Черновой ряд `S-301…S-310` в конфиге положен как раз на такую дугу — можно
взять за образец формы, но не за готовую разметку.

## lat/lon ставятся по 2ГИС

Пиксельные координаты и географические — независимы. `lat`/`lon` места и
`approach` (точка подъезда, куда вести маршрут) проставляются **руками
по 2ГИС**, по месту на карте.

Валидатор проверяет только попадание в рамку Владивостока
(42.8–43.5 / 131.5–132.3) — это ловит опечатки, но не ошибку в 50 метров.
Примеры из `CLAUDE.md` (43.115141, 131.885341 — Clover House) к нашим камерам
отношения не имеют, это заглушка из спеки.

В редакторе есть поля «Базовые lat/lon» — они подставляются новым объектам,
чтобы не начинать с пустого места. **Это заготовка, а не координата**:
каждую точку всё равно надо уточнить.

Все координаты в текущем черновике — приблизительные и по 2ГИС **не сверены**.

## Отдача в backend

```bash
python tools/make_seed.py
```

Собирает из `config/cameras.yml`:

- `seed/spots.json` — по модели `ParkingSpot` из `CLAUDE.md`, плюс
  `roi_frame_size: [w, h]` (без него пиксельный `roi_polygon` бессмысленен:
  камеры разного разрешения);
- `seed/zones.json` — зоны с `capacity` и полигоном.

Стартовый статус у всего — `unknown`, `confidence: 0.0`. Пока CV не прислал
детекцию, показывать место свободным нельзя.

## Чего редактор не умеет

**Комментарии внутри структуры YAML не переживают round-trip.** Редактор
разбирает файл в объекты и печатает заново; сохраняется только шапка файла
(комментарии до `version:`). Пояснение к конкретному месту пишите в поле
`notes` — оно часть схемы и доезжает до конфига. Общие заметки — в шапку.

Якоря, алиасы и многострочные блоки YAML редактор тоже не поддерживает —
в нашем конфиге их нет.

`config/backups/` растёт с каждым сохранением; его стоит добавить в
`.gitignore`.
